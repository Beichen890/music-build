# 旋律去重复 / 变奏改写

用于"旋律重复太多"的修改需求。核心原则：**只改音高，不动节奏。**
好处是歌词对位、拆音、长音处理、混音全部不会失效 —— 改动面小、可回退、可反复重跑。

---

## ⚠️ 先读这一条：这项任务极易失败（真实翻车记录）

**结论先行：旋律改写是作曲，不是工程。除非用户明确要求并且你能验收，优先动配器而不是动旋律。**

一次真实翻车：《盛夏的黄昏》把 36% 的重复降到 6%，量化指标（和弦吻合度、音程分布、
跨度）全部通过，但用户听完说"旋律有点莫名其妙，根本不是一首歌"。

原因只有一个，而且**用我当时的指标查不出来**：

| 指标 | 原旋律 | 我改的 |
|---|---|---|
| 同音反复率（相邻音高相同） | 全曲 1.0% / **改动段 0.0%** | 全曲 3.8% / **改动段 6.6%** |

原作者的旋律在那些段落**一次同音反复都没有** —— 这是他的风格底线。
我写进去 6.6%，并且把"上行琶音"当成旋律音型用（`F5 A4 C5 F5 A5`，一路来回弹），
离开钢琴音色单独听就是"来回敲"。

**教训：把配器手法（琶音、踏板音、分解和弦）当作旋律本身，是这类任务最常见的死法。**
旋律是"一条有方向的线"，不是"每小节一个手法的拼接"。

### 动手前必须做的三件事

1. **先测原旋律的风格红线**：同音反复率、级进率、大跳率、方向反转率、
   跨度、以及"一句里音区是单向上行还是来回"。改动后的每一项都不能比原曲更极端。
2. **保留乐句身份**：每句的**前 2–3 个音和末音**尽量不动，只重写中间。
   一句的"开口"和"落点"变了，听众就不认这是同一首歌了。
3. **同音反复率与原曲持平**。原曲是 0% 就必须是 0%；出现连续两个同音就是危险信号
   （除非原曲本来就用它，例如念白式段落）。

### 更稳的替代方案（优先推荐）

重复感**不等于**必须改旋律。先考虑：
- 换配器（第二遍主歌撤掉 Pad 换成吉他、换鼓型、加减乐器）
- 换织体（第二遍副歌加八度加倍、弦乐进场）
- 换动态与音区布局（第二次副歌乐器更满）
- 只有"最后一遍副歌升调"这类**整体平移**是安全的旋律层面操作

**这些都不会破坏旋律，而且往往是专业上的正确答案。**
只有当用户明确"就是要不一样的旋律"、并且愿意反复验收时，才动音高。

## 1. 先量化，不要凭感觉

把旋律按 **2 小节一个单元**切片，用音高序列做签名，找完全相同的单元：

```python
sig[u] = tuple(pitch for note in unit_notes(u))
first = {}
for u in sorted(sig):
    if sig[u] in first:  print('unit%d == unit%d' % (u, first[sig[u]]))
    else:                first[sig[u]] = u
```

一次真实的测量结果（100 小节流行曲）：**18 个单元 = 36 小节 = 36% 是完全复制**，
典型分布是：

- 第二遍主歌 = 第一遍主歌（逐音相同）
- 第二遍预副歌 = 第一遍预副歌
- 第二遍副歌 = 第一遍副歌（整段）
- 最后一遍副歌 = 第一遍副歌升调（音高不同，但轮廓逐音平移）
- 副歌内部还有自复制（12 小节副歌 = 4 小节 ×3，第 3 块 = 第 1 块）

**只看"有没有重复"没意义，要看到"哪几处、多少小节"。** 目标值：改完剩 **6%–15%**。

### 同时必须测"风格红线"（比重复率更重要）

```python
iv = np.diff(pitch_seq)                       # 同句内相邻音程
zero = (iv == 0).mean()                       # 同音反复率  ← 最关键的指标
step = (np.abs(iv) <= 2).mean()               # 级进率
big  = (np.abs(iv) >= 5).mean()               # 大跳率
nz = iv[iv != 0]; d = np.sign(np.diff(nz)); d = d[d != 0]
rev  = (d[1:] != d[:-1]).mean()               # 方向反转率
span = np.ptp(pitch_seq)                      # 跨度
```

**改动后的每一项都不许比原曲更极端**，尤其是同音反复率。
真实数据（原 → 我改，改动段）：同音反复 0.0% → 6.6%（翻车），
级进 73.6% → 75.2%，大跳 5.8% → 7.4%，跨度 19 → 19 半音。
**注意：后面三项都"通过"了，唯一超标的那一项才是致命的。**

## 2. 哪些重复必须留，哪些必须改

| 保留 | 理由 |
|---|---|
| 副歌 hook 的陈述（第二遍副歌的前 4–6 小节） | 没有重复就没有记忆点，这是曲子的身份 |
| 最后一遍副歌的升调重复 | 全音/三度升调重复是强化手段，不是偷懒 |

| 必改 | 理由 |
|---|---|
| 主歌 2 = 主歌 1 | 听众在第二遍主歌注意力最高，逐音重复等于浪费 |
| 预副歌 2 = 预副歌 1 | 推进段落重复会让人提前知道副歌什么时候来 |
| 副歌后半段的原样复制 | 12 小节副歌里后 6 小节复制前 6 小节，等于把副歌打对折 |
| 副歌内部的自复制块 | 同上 |

## 3. 五类变奏手法（按使用场景选）

均为**同节奏换音高**，音位数与时值完全不变。

**① 音程压窄 + 音区下移**（"被规整"）
适合第二遍主歌。把原旋律向均值音高压缩（音程缩到 1–2 半音为主）、整体降 2–4 半音，
只留最后一句向上挣一次。
效果：同一段旋律听起来"变小了、变顺从了"，但仍是同一首歌。

**② 上行琶音**（用和弦音堆上去）
适合需要"生长感/推进感"的句子。整小节只用该和弦的和弦音，从低到高排。
因为全是和弦音，听感非常稳，同时轮廓和原旋律完全不同。

**③ 同音反复（凝滞）**
适合"僵住 / 数不下去 / 卡住"的语义。**最多用 1–2 小节**，多了会像坏掉。
放在琶音之后对比最强：一松一紧。

**④ 同节奏换音高的 tag 变奏**
副歌结尾不要原样复制前 4 小节。保留节奏（这是 hook 的节奏），换音高：
- 上升型 tag：一路拱到全曲最高音再落回，制造第二次高潮
- 下降型 tag：逐级下行收束，适合接间奏/留白

**⑤ 碎片化下行 + 原地摆动**
适合全曲收尾。音程逐步缩小、音区逐步下降，末 2 小节用两个音来回摆动（"照常/算了"）。

## 4. 校验：和弦吻合度必须过关

改完逐个音对和弦判类：

```
和弦音      pc ∈ {根, 三, 五}
调内经过音  pc ∈ 该调音阶（但非和弦音）
调外音      其余
```

**调外音必须为 0。** 和弦音占 60%+ 是健康区间（真实测量：105 个改动音 =
67 和弦音 + 38 调内经过/延留音 + 0 调外音）。

调内经过音集中在弱拍、八分/十六分位置没问题；**不要落在长音和乐句末音上**。

## 5. 必踩的坑：其他轨也在叠奏主旋律

改旋律前先查一遍：**有没有别的轨与主旋律"同位置、同音高"**。

```
同音高重复 → 几乎肯定是故意叠奏（pad、双钢琴、人声加倍），必须跟着改
八度重复   → 可能只是和弦音巧合（贝斯根音、鼓的 pitch 恰好八度关系），不要乱动
```

判断依据：看**起点是否与旋律音同时开始**。同时开始 = 叠奏；只是音高恰好相同 = 巧合。
真实测量：某曲 Warm Pad 有 33 个音与旋律同音高，其中 8 个落在旋律改动位置 → 需要跟随。

只跟随"完全同音高"的叠奏，**不要按八度推测**，否则会误改伴奏（鼓和贝斯的音高数值
与和声无关，按八度改会直接把节奏打乱）。

## 6. 验证：渲染 A/B + 逐小节差异定位

改完必须能用耳朵判断，而且能证明"只改了该改的地方"：

```python
# 两版渲染成 wav 后，逐小节算差值
seg = np.abs(orig - rev).mean(axis=1)[:n//win*win].reshape(-1, win).mean(axis=1)
hot = [i+1 for i in range(len(seg)) if seg[i] > seg.max()*0.20]
```
`hot` 应与"改动小节清单"完全吻合，多出来的就是 bug。
（注意 4/4、100 BPM 时 1 小节 = 2.4 s；窗口索引换算成小节号时别写成 `i*2+1`。）

同时给出：
- 全曲 A/B 两个文件
- **段落对比文件**（原版一段 → 1.2 s 静音 → 修订版同段），最容易听出差别
- 纯旋律 A/B（只留旋律轨），用于判断旋律本身

## 7. 实现要点

- 以"**音节组**"为单位改音高：主音 + 其后的延音段（OpenUtau/MIDI 里的 `+`）
  必须一起改，否则拆音段和主音会音高不一致。
- 改 `tone:` 字段时按出现顺序对齐音符：`.ustx` 里 `tone:` 行数 == 音符数，
  第 i 行对应第 i 个音符，可安全批量替换。
- 脚本**读原始备份、写目标文件**，不要就地覆盖 —— 这样每次调整都能重跑。
