# 替换采样音源（Salamander / sfizz 流程）

用于「GM 音色太糙 / 换音源值不值」这类需求。核心结论先行：

> **GM 音源丢掉的不是音色，是你的演奏数据。**
> 换不换，取决于 MIDI 里有没有力度分层和 CC。

---

## 0. 先算这笔账：值不值得换

逐条检查源 MIDI 的演奏信息，缺什么就换什么能补回来：

| MIDI 里有的 | GM 音源的处理 | 真实采样音源的处理 | 值得换？ |
|---|---|---|---|
| 力度 ≥ 8 档 | 只影响音量 | 8–16 层采样切换 | ✅ 直接可听 |
| CC64 延音踏板 | **完全忽略** | 踏板采样 + 踏板噪声 | ✅ 最强理由 |
| 表情 CC（11/1/10） | 部分支持 | 支持 | ✅ |
| 音区超出 GM 覆盖 | 音色突变 | 自然处理 | ✅ |
| 单一力度、无踏板 | — | — | ❌ 白换 |

**结论规则**：如果源 MIDI 全曲 **0 个 CC 事件**，那先加表情再加音源，否则换来的钢琴也只是"更响的电子琴"。

## 1. 工具链（全免费、全离线、不需要 DAW）

### Salamander Grand Piano V3
- **来源**：`github.com/sfzinstruments/SalamanderGrandPiano`（master 分支 zip，716 MB）
- **许可**：CC-BY 3.0，免费
- **内容**：Yamaha C5 真实采样，88 键 × **16 个力度层** = 641 个 FLAC
- **sfz 特色**：`cc64 Sus Pedal`、踏板噪声、琴弦共振（`cc20`）、击槌噪声（`cc21`）、释放采样（`trigger=release`）、三段力度曲线（`vel_01..16.txt`）

> ⚠️ 解压后 sfz 在仓库子目录里（`SalamanderGrandPiano-master/`），不是 zip 根目录。

### sfizz（离线渲染器）
- **来源**：`github.com/sfztools/sfizz` releases，win64 zip 仅 7.9 MB
- **许可**：BSD-2
- 自带 `sfizz_render.exe`，纯命令行

```
sfizz_render --sfz <sfz> --midi <mid> --wav <out> -s 44100 -p 256 -b 2048 --use-eot
```

### 🚨 必加 `--use-eot`
不加它，sfizz 会把尾音一直渲染下去：**4 分钟的曲子跑 9 分钟未完成**（还被 `timeout` 杀掉，留下 `frames=0` 的残缺 WAV —— sfizz 流式写盘，不回填 WAV 头）。
加上之后同一首曲子 **14 秒**。

**残缺文件的识别方法**（不影响文件大小，只看头）：
```python
b = open(wav,'rb').read(80)
j = b.find(b'data')
print(struct.unpack('<I', b[j+4:j+8])[0], os.path.getsize(wav))   # data size 应 = 文件大小 - 44
```

## 2. 测量：别用宽带 FFT 占比

**这是本次最大的教训。**

宽带 FFT 分频段能量占比会被中低频绝对能量主导，导致「高频占比 0.1%」这类**看起来很吓人但完全错误**的结论 —— 真实钢琴的能量本来就在基频与低阶泛音。

### 正确方法：1/3 倍频程逐带 RMS（相对基准频）

```python
from scipy.signal import butter, sosfiltfilt
def oct_db(m, sr, ref=500):
    out = {}
    for f0 in [125,250,500,1000,2000,4000,8000,12000]:
        lo,hi = f0/1.41, min(f0*1.41, sr/2*0.99)
        sos = butter(4,[lo/(sr/2), hi/(sr/2)], btype='band', output='sos')
        y = sosfiltfilt(sos, m[:int(3*sr)])
        out[f0] = 20*np.log10(np.sqrt(np.mean(y**2))+1e-30) - out.get(ref,0)
    return out
```

必须**两版用同一方法测**才有可比性。

### 本次实测结果（同一组单音）

| 频率 | GM 钢琴 | Salamander | 差 |
|---|---|---|---|
| 250 Hz | +6.4 | −3.6 | −10.0 |
| 500 Hz | 0 | 0 | — |
| 1 kHz | **−1.6** | **−12.1** | −10.5 |
| 4 kHz | −21.3 | −23.4 | −2.1 |
| 8 kHz | −46.2 | −49.4 | −3.2 |

**真实钢琴比 GM 暗，不是亮。** GM 在 1 kHz 只降 1.6 dB = 金属味；真实钢琴降 12 dB = 基频主导。

> ⚠️ 「GM 高频只有 0.1%，所以要换音源补高频」——这个推理是错的，别再犯。

## 3. 换源之后必须重做的混音

**真实采样的频谱形状和 GM 完全不同**，原来的 EQ 参数直接套会出事。

### 逐轨实测差异（本次）

| 轨 | 60–120 Hz GM | 60–120 Hz 真实 | 差 |
|---|---|---|---|
| 主旋律钢琴 | 0.1% | 0.2% | +0.2 |
| **伴奏钢琴** | **2.3%** | **17.1%** | **+14.9** |
| Warm Pad | 0.0% | 0.0% | 0.0 |
| 贝斯 | 30.4% | 31.9% | +1.5 |
| 鼓 | 27.3% | 27.3% | 0.0 |

**规律**：真实钢琴**低音区乐器**（伴奏钢琴、和声铺底、吉他）的琴箱共鸣会暴涨 10–15 倍；旋律轨变化不大。

### 症状与修法

| 症状 | 修法 |
|---|---|
| 总线 60–120 Hz 涨超 8 个点、听感发闷 | 伴奏钢琴 `hpf` 从 85 → **240 Hz**；旋律钢琴 `hpf` → **180 Hz**；Pad `hpf` → **260 Hz** |
| 底鼓与琴箱撞车 | 底鼓 `peak 85 -3dB`、`gain -3.5dB`；镲片 `highshelf 7000 +5dB` |
| 250–500 Hz 变薄（不是缺点） | 真实钢琴该段占比天然低 ~17 个点，是「从闷到透」的交换，别硬补 |
| Pad 盖住旋律 | 幅度 −7 dB、`ms_width 1.55` 推宽 |

**原则：低频归底鼓，中频归钢琴。** 不要试图用均衡「修回」参考混音的低中频堆积——那是 GM 渲染的病，不是目标。

## 4. 严格 A/B：只让一个变量变

**必须让对照组的其余分轨字节完全相同。**

本次踩过的坑：对照组用了旧 stems（从另一份 MIDI 渲的），导致差异混进了「MIDI 换了」和「处理链换了」两个变量，A/B 完全无效。

正确做法：
```
stems_real/       ← 真实采样钢琴 + 其余 5 轨
stems_gm_only/    ← GM 钢琴（从同一份 MIDI 渲）+ 其余 5 轨（直接 copy 过去）
```

音频对照脚本要点：
- **段落级**归一到相同 LUFS（不是只归一峰值）
- 选对比窗口：主歌 / 副歌 / **乐器最少的留白段**（最容易听出音源差别）
- 每段之间留 1.5 s 静音 + 2.5 s 停顿

## 5. 已知测量指标的失效场景

写这类分析脚本时注意：

| 指标 | 何时失效 |
|---|---|
| **attack time**（起音时间） | 连奏旋律（legato）——找不到明显的瞬态间隔，量出来全是 0 |
| **tail length**（延音尾巴） | 需要音与音之间有断裂；踏板连着时测的是整段的衰减，不是单音 |
| 宽带 FFT 频段占比 | 见上文，中低频主导时结论错误 |

失效时改用**对照法**：同一组单音、同一分析方法、两版并列。
