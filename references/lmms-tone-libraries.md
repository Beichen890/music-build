# LMMS 音色库：格式边界与实测

> **来源**：B 站公开教程 / 专栏 / 测评整理（采集 2026-11-11，973 条去重视频、8 个课程视频下载抽帧）。逐条来源见文末「来源索引」，学习清单见 `bilibili-study-map.md`。  
> **制作口径**：默认在 DAW 里作曲编曲（MIDI + 采样音源 + 合成器 + 自动化 + 混音）；真实乐器、采样、合成器音色都是合法音色来源，不做「原声 vs 电子」的出身审查。  
> **范围分流**：不默认做吵闹的电子舞曲风格（EDM / House / Techno / Trap / Dubstep / 鼓机 drop / riser / 泵感侧链 / supersaw lead），这类内容单独收在 `references/electronic-styles.md`，主线不混。  
> **主用途**：情绪驱动 + 场景感双轴 + 钢琴 / 小提琴 / 手风琴三件套；合成器在这里是色彩与空间层（pad / bell / soft lead / 铺底），不是舞曲骨架。  
> **用法**：数值是起点不是法则，以耳朵为准；与本技能既有硬规则冲突时，以技能规则为准。  
> **情绪驱动**：按情绪查配方 `emotion-arrangement-recipes.md`、按情绪查和弦 `emotion-chord-index.md`、钢琴/小提琴/手风琴写法 `core-instruments.md`。  
> **标注**：【源】/【事实】= 可核实；【验】= 交叉验证；【经验】/【通用理论补充】= 惯例或未单条核实，可放心改。

## 1. 先看格式：LMMS 能吃什么，不能吃什么【事实】

音色质量的上限，一半由格式决定。LMMS 1.3 的边界比多数人以为的更窄：

| 格式                       | LMMS 1.3         | 影响                                  |
| ------------------------ | ---------------- | ----------------------------------- |
| **SF2 / SF3**（SoundFont） | ✅ 原生 `sf2player` | 最稳的采样库路线                            |
| **GIG**（GigaSampler）     | ✅ 原生 `gigplayer` | 老格式，现成资源少                           |
| **VST2 64 位 `.dll`**     | ✅ 可挂             | 能用，但**不保存插件状态**（见坑 1）               |
| **VST3 `.vst3`**         | ❌ **完全不支持**      | **现代免费音源的最大障碍**                     |
| **SFZ**                  | ❌ 无 SFZ 播放器      | Salamander / Sonatina / VSCO2 全部卡在这 |
| **LV2 / CLAP**           | ❌                | —                                   |
| **音频输入 / 录音**            | ❌ 无输入通道          | 虚拟音频线送声这条路不成立                       |
| 原生合成器 / 采样（wav/ogg/flac） | ✅                | 42 种内置乐器 + 421 采样                   |

**由此推出一条硬结论**：

> 你在网上看到的「免费音色库推荐」，八成是 **VST3 或 SFZ**。  
> 这两类在 LMMS 里**直接用不了**，必须先转换或换路线，否则装完就是个空壳。

### 坑 1：VST2 不保存状态

LMMS 不写 VST 的 `<chunk>`（state），所以每次打开工程，插件都回到**默认音色**。  
这意味着：能挂 ≠ 能用。挂上 TAL-NoiseMaker 后你调的音色，重新打开工程就没了。  
**结论**：VST2 在 LMMS 里只适合「吃默认音色就够」的插件（合成器、效果器），  
不适合需要加载采样/工程的采样器（sforzando、Kontakt、Decent Sampler 都会空）。

## 2. 实测：GM 为什么「廉价」【事实，本机数据】

不是审美问题，是**采样结构**问题。用 `sf2_audit.py` 解析两套 GM 的 `pdta` 头：

| 指标          | FluidR3_GM（141 MB） | GeneralUser GS（31 MB） |
| ----------- | ------------------ | --------------------- |
| 采样总数        | 1418               | 920                   |
| **带循环点的采样** | **100%**           | **100%**              |
| 采样长度中位数     | 1.16 s             | **0.30 s**            |
| 最短 10% 采样   | 0.18 s             | **0.01 s**            |
| 钢琴采样数       | 52                 | 25                    |
| 小提琴采样数      | 28                 | **11**                |
| 弦乐采样率       | 32k / 44.1k        | 含 **11025 Hz**        |
| 最长采样        | 13.0 s             | 4.3 s                 |

**三个致命点**：

1. **100% 采样带 loop** —— 所有长音都是「一小段波形循环播放」。钢琴、弦乐的长音会露出  
   周期性的机械感，尤其在尾音和跨音区时。
2. **GeneralUser 的采样中位长度只有 0.30 秒，最短 0.01 秒** —— 0.01 秒基本就是一个波形周期，  
   完全靠循环撑。这就是「廉价 GM 味」的物理来源。
3. **GeneralUser 的小提琴只有 11 个采样覆盖整个音域** —— 每个采样要拉伸好几个半音，  
   音色随音高漂移；弦乐用了 **11025 Hz** 采样率，5.5 kHz 以上是空白。

### 力度层：真正的分水岭【实测】

同一音（C4）用 vol=30 与 vol=110 各渲染一次，做**样本级互相关**：

| 音源                     | 最大相关      | 判定              |
| ---------------------- | --------- | --------------- |
| **Salamander（自建 SF2）** | **0.830** | 换了采样——力度层真的在切换  |
| FluidR3_GM             | 0.966     | **同一条采样，只是改音量** |
| GeneralUser GS         | 0.930     | **同一条采样，只是改音量** |

这条数据比任何形容词都硬：

> **GM 的「强弱」是音量旋钮，不是演奏力度的变化。**  
> 所以 GM 做不出「弱奏时音色变暗、强奏时泛音炸开」的表情——而这正是情绪驱动编曲最需要的东西。

## 3. 突破方案：五条路线，按推荐度排序

### 路线 A：自建 SF2（已实现，推荐）

本机已有 **Salamander Grand Piano V3**（Yamaha C5，48 kHz / 24-bit，16 力度层，  
采样 4–25 秒自然衰减），但它是 **SFZ**，LMMS 不认。  
已写 `sfz2sf2.py` 把它转成标准 SF2，LMMS 直接加载。

**实测结果**：

| 项       | 数值                                              |
| ------- | ----------------------------------------------- |
| 输出文件    | `D:\LMMS13\data\soundfonts\SalamanderV3-4L.sf2` |
| 体积      | 138.3 MB                                        |
| 音区      | 120 zones（34 音区 × 4 力度层，少数超高音区源采样缺失）            |
| 格式      | 44100 Hz / 16-bit / mono / **无循环点**             |
| 采样长度中位数 | **24.0 s**（对比 GM 的 1.16 / 0.30 s）               |
| LMMS 渲染 | ✅ `peak 0.891 / silent: false`                  |
| 力度层     | ✅ 样本相关 0.830，真切换                                |

**用法**：

```bash
node D:/lmms-cli/dist/lmcli.mjs setSoundfont song.mmp --track Piano \
     --file D:/LMMS13/data/soundfonts/SalamanderV3-4L.sf2 --patch 0
```

**代价**：138 MB 会全部载入内存。工程多开时注意可用内存（本机日常可低至 1–2 GB）。  
要更省，用 `--layers 4 --rate 32000` 重生成，体积降到约 100 MB。

**局限（老实说）**：SF2 只保留 key/velocity 映射，Salamander 原版的  
release 采样、踏板噪声、锤击噪声、CC 微调全部丢失。所以它**不是完整还原**，  
但钢琴主体（音头 + 自然衰减 + 力度层）是完整的，这点远胜 GM。

### 路线 B：外部宿主渲染 stem → LMMS 当音频轨（推荐，对应「VST 宿主」）

**先纠正一个常见误解**：

> 「用虚拟音频线把 VST3 的声音送进 LMMS」——**这条路在 LMMS 上不成立**。  
> 因为 LMMS **没有音频输入通道**（录音功能 GUI 独占，且不接受外部音频流）。  
> 虚拟音频线（VB-CABLE / VoiceMeeter）能把声音送到 OBS、Reaper，但送不进 LMMS。

**能走通的做法是离线渲染**：

```
外部宿主（能加载 VST3 的任何宿主）→ 导出 wav stem → lmcli addClip → LMMS 混音
```

已实测链路可用：

```bash
lmcli addClip song.mmp --path stem.wav --pos 0 --len "2 bars"
# 自动建采样轨，渲染结果 peak 0.891 / silent: false
```

**本机的现成宿主**：**FL Studio 已装**，且 `FL Studio VSTi.dll` 是 **x64 VST2**，  
理论上可以直接挂进 LMMS（但受坑 1 限制，VSTi 打开是空工程，不实用）。  
更现实的用法是：**在 FL 里编好、渲染 wav，再进 LMMS 混音**，或者干脆 FL 出成品。

**这条路的价值**：绕开 LMMS 的全部格式限制。那些在 LMMS 里**用不了**的 VST3 音源都可以在外部宿主里用——Vital、Surge XT、Decent Sampler、Spitfire LABS，只要最后变成 wav。

**代价**：不是实时的，改一个音要重新渲染一遍。适合「音色定型后批量出 stem」，  
不适合边弹边改。

### 路线 C：VST2 64 位直接挂（可用，但受限）

本机已装（`vstList` 实测）：

| 插件                   | 类型   | 状态        |
| -------------------- | ---- | --------- |
| TAL-NoiseMaker       | 合成器  | ✅ 可挂可出声   |
| TAL-Elek7ro-II       | 合成器  | ✅         |
| TAL-Bitcrusher       | 效果   | ✅         |
| TAL-EQ               | 效果   | ✅         |
| FL Studio VSTi (x64) | 宿主内嵌 | ⚠️ 能挂但空工程 |

**注意**：这是原生合成器路线，不是采样器路线。做 pad / bell / soft lead 够用，  
做不了「真实钢琴」。要用采样器，就得走路线 A 或 B。

### 路线 D：原生合成器 + LADSPA（被低估）

LMMS 有 **42 种内置乐器** + **250 个 LADSPA 效果器**。  
「廉价」的不是引擎，是**没调过的默认音色**。可行的做法：

| 目标音色     | 做法                                                  |
| -------- | --------------------------------------------------- |
| 弦乐 pad   | `vibedstrings` + LADSPA 合唱 + 低通 6 kHz               |
| 钢琴质感     | `tripleoscillator`（正弦 + 少量三次谐波）+ 快 attack/长 release |
| 手风琴      | `tripleoscillator` 三振荡器微失谐（±8 cent）+ 方波混合           |
| 钟 / bell | `OPL2` 或 `watsyn` + 长 release                       |

这条路的上限低于真采样，但**完全免费、零加载时间、可随时改参数**，  
适合做「色彩层」而不是主角。

### 路线 E：采样直读（`audiofileprocessor`）

LMMS 自带 **421 个采样**，其中有一批真实乐器单音：  
`violin_fingered01.ogg`（1.94 s）、`violin_pizzicato01.ogg`、`cello01.ogg`（1.87 s）、  
`e_piano_accord01.ogg`（3.72 s）、`piano01.ogg` 等，都是 44.1 kHz。

**局限**：单采样、无力度层、跨音域靠 pitch shift，拉太多就失真。  
**适合**：短句、点状音色、拟音（本机还有 181 个 nature 拟音采样）。

## 6. 可复现脚本

| 脚本                    | 作用                                         |
| --------------------- | ------------------------------------------ |
| `sf2_audit.py`        | 解析 SF2 的 `pdta`（采样数、loop 比例、采样率、长度、zone 数） |
| `sfz2sf2.py`          | SFZ + 采样 → 标准 SF2（当前适配 Salamander 结构）      |
| `tone_test.py`        | 同一段 MIDI 灌进多个音源，批量渲染                       |
| `tone_analyse.py`     | 算频谱重心、频段占比、衰减、crest factor                 |
| `bili_search_loop.py` | 循环 / 节奏 / 音源主题的 B 站采集                      |

**踩过的坑（写脚本时避开）**：

1. RIFF 子块的 size 必须为**偶数**，否则 FluidSynth 直接拒绝（`odd size ... Rejecting file`）。  
   要把 padding 写进 payload 内部，不能加在 chunk 外面。
2. `phdr` 末条（EOP）的 `wPresetBagNdx` 必须等于**实际 zone 数**，不是 0，  
   否则报 `Preset bag chunk size mismatch`。
3. 钢琴不要设 loop（`sampleModes=0`），让它自然衰减；设了反而会有接缝。
4. LMMS 渲染出来是 **float32 wav**，`wave` 模块读不了（`unknown format: 3`），  
   要先 ffmpeg 转 `pcm_s16le`。
5. FluidSynth 渲染需要 **MIDI 输入**，不接受音频文件——要验证 SF2 先写个小 MIDI。

## 8. 补上三件套的缺口（2026-11-11 深夜实测）

上一轮只解决了钢琴。这一轮把手风琴和小提琴也用真实录音换掉了，并且把  
「音色好」从形容词变成了可以复现的数字。

### 8.1 转换器升级：`sfz2sf2.py` 现在是通用 SFZ→SF2

原来只会读 Salamander 专用的 `region.txt`。现在加了通用模式：

```bash
python sfz2sf2.py --sfz "某音源/preset.sfz" --mono --xfade 40 --out out.sf2
```

支持 SFZ 里真正会用到的那些 opcode：

| SFZ                                  | 落地到 SF2                                       | 说明                                |
| ------------------------------------ | --------------------------------------------- | --------------------------------- |
| `lokey/hikey/lovel/hivel`            | gen 43 / 44                                   |                                   |
| `pitch_keycenter`                    | gen 58 overridingRootKey + shdr originalPitch |                                   |
| `tune`（音分）                           | shdr pitchCorrection + gen 52 fineTune        | 超过 ±99 的部分进 fineTune              |
| `volume`（dB）                         | gen 48 initialAttenuation                     |                                   |
| `loop_start/loop_end/loop_mode`      | shdr startloop/endloop + gen 54               |                                   |
| `ampeg_attack/decay/sustain/release` | gen 34/36/37/38                               | 秒→timecents；%→cB（`-200·log10(v)`） |
| `trigger=release` 区                  | **丢弃**                                        | SF2 没有可移植的 release trigger        |

**新加的「循环交叉淡化」是这一轮最有用的东西。** SF2 不支持 crossfade loop，  
只能硬跳。`--xfade 40` 会把循环尾巴的 40 ms 和循环点之前的音频做等权混合，  
让 `x[le-1] == x[ls-1]`，于是接缝处值和斜率都连续：

| 对象                        | 接缝跳变（÷ 本段自然步长）                   | 相位相关      |
| ------------------------- | -------------------------------- | --------- |
| FreePats 手风琴，原库 loop，不淡化  | 中位 **1.31**，p90 3.05，max 6.48    | 0.974     |
| 同上，加 40 ms 交叉淡化           | 中位 **0.68**，p90 1.60，max 3.17    | **1.000** |

### 8.3 小提琴：University of Iowa MIS 2012（可商用，注明出处即可）

> 这批素材已被 §9 的 VSCO 2 CE 取代（原因是每个音都是 1.7 s 渐强，做不出稳态）。  
> 下面保留的是当时的做法，仍然适用于「要用这批音」的场景。

FreePats 没有弦乐（OrchestralStrings 目录是 403/404），Sonatina 官网已死  
（`sso.mattiaswestlund.net` 返回 204）。改用爱荷华大学音乐仪器采样库：

```bash
# 68 MB，arco 单声道 16/44.1
https://theremin.music.uiowa.edu/sound%20files/MIS/Strings/violin2012/
      Violin.arco.mono.1644.1.zip
```

**它不是一个音一个文件**，而是一个文件里连奏一条半音阶（`sulG.C4B5` = C4 到 B5  
一路拉下来），文件里没有循环点、没有音高表。所以 `iowa_violin.py` 做了四件事：

1. **按预期音高切片**：文件名给出升序半音列表，逐个在频谱里找该音高的最长  
   连续帧段。比「按静音切」可靠——颤音会让电平掉下去，静音切法会把一个音  
   切成两半，之后全部错位一个半音。
2. **顺手验证**：每个音实测基频 vs 预期，中位偏差落在 **-21…+19 音分**，  
   36 个文件里只有 3 个中位超过 20 音分（颤音把谱峰拉宽所致）。
3. **自动找循环点**：只在 **最响的稳态处** 找（这批录音是「渐强到乐句末再断」  
   的 swell 型，不是平直的持续音），循环长 140–420 ms，相位相关中位 **0.999**。
4. **按持续音 RMS 统一增益**，而不是按峰值。理由见 §8.5。

- 落地：`D:/LMMS13/data/soundfonts/ViolinIowa.sf2`（23 MB，**111 zones**）。
- 力度层：pp / mf / ff **三条独立录音**。同一音高跨层波形相关中位 **0.00**  
  （GM 是 0.93–0.97 = 同一个采样改音量），这就是「真换采样」的硬证据。
- **风格提醒**：这批音是 2 秒左右的「弓压渐强」型，不是无限持续的 legato 弦乐。  
  用来写**悲伤的推进句、宏大的长音铺底**很合适（每次换音都有自然的渐强），  
  写快速连奏会露馅——那种段落用它做叠加层，主旋律交给钢琴或合成器。
- 音域取 B2–G6（MIDI 55–91），超出就拉伸，别用。

### 8.4 ⚠️ lmcli / LMMS 的键位比 SF2 高一个八度

实测：`addNotes` 写 `key=C4`，三个不同 SF2（Salamander / 手风琴 / FluidR3 GM）  
渲染出来的基频**都是 523.8 Hz**，即 MIDI 72 而不是 60。

原因就是 LMMS 内部 `C5 = 60` 的老约定：卷帘上标 C4 的位置，送进 SF2 的是 72。

两个后果：

- **做 A/B 无所谓**，只要两边用同一组键名，相对关系是对的。
- **自己写 SF2 的音域必须按这个偏移核对**：音域写成 60–72 的采样，用  
  `key=A4`（69）去测会**完全没声音**（69 送进去是 81，落在音域外）。  
  测音源用 `key = 目标 MIDI − 12` 的写法，或者干脆在 LMMS 界面里点。

### 8.5 响度：别用峰值归一，用持续音 RMS

Iowa 的弓起音是瞬态、强拍在后半句。按峰值归一会让整个音色比 GM **低约 10 dB**  
（渲染实测 rms 0.062 vs 0.197），用户第一反应会是「新的更难听」。  
改成「以 ff 层循环段的 RMS 中位数为基准，统一推到 0.13」，pp/mf/ff 的相对  
强弱完全保留，整体响度才和 GM 站在同一起跑线。A/B 导出时再用 ffmpeg  
`loudnorm=I=-16` 对齐一次。

## 9. 换掉小提琴源，以及一个让长音断掉的格式 bug（2026-11-12）

上一轮交付后用户只说了两个字：**「太喘」**。这一节是把这两个字拆成数字、  
找到根因、换掉音源的完整过程。中间挖出来的格式 bug 比音色本身更重要。

### 9.1 「喘」要测的不是电平极差，是首尾落差

第一版我拿 `p90/p10`（一个循环周期内的电平极差）当指标，这是错的：真实弦乐  
的颤音本身就是 5–6 Hz 的音量摆动，**好音色也会被这个指标判死**。

耳朵听到"喘"是另一回事——循环一圈结束时电平比开始时高，于是每次回头都像  
重新吸一口气。所以指标应该是**循环段首 1/4 与末 1/4 的均值之差**（下称 trend）：

| 音源                | trend（中位）    | trend p90    | 起音到稳态（中位 / p90）     |
| ----------------- | ------------ | ------------ | ------------------- |
| Iowa 原始（未处理）      | **+1.05 dB** | 4.75 dB      | 0.20 s / **1.30 s** |
| Iowa + 包络压平       | +0.05 dB     | 0.80 dB      | 0.04 s / 0.08 s     |
| VSCO 2 CE（选点加惩罚后） | **−0.25 dB** | 0.70 dB      | 0.17 s / 1.36 s     |
| FluidR3 GM        | −1.90 dB     | **45.75 dB** | 0.01 s / 0.28 s     |

GM 那一列很说明问题：中位数看着还行，p90 却是 45 dB——说明它有大量采样在  
一个循环周期里电平能掉几个数量级，弦乐群听起来"抖"就是这么来的。

`sf2_envelope.py` 就是量这两件事的。

### 9.2 为什么 Iowa 那批修不好

拆开看单个音（`Violin.arco.ff.sulA.A4B4`，A4）：

```
0.1s −16.5 dB  0.5s −10.0  1.0s −6.8  1.3s −5.2  1.5s −0.4  1.6s −0.8  1.7s −9.1  1.8s −21
```

**从第一个音头到乐句末，一路渐强 1.7 秒，峰值只出现在最后 0.2 秒，然后断掉。**  
这不是"稳态上叠了一点颤音"，是根本没有稳态。任何循环点都落在斜坡上。

我试过两条补救：

1. **裁掉渐强**（`--preroll 0.16`）：把 1.5 秒渐强砍成 0.16 秒弓起音。
2. **重写慢包络**（`envelope_flatten`：20 ms RMS 估计包络 → 反相增益 → 15 ms  
   平滑 → 变成「短起音 + 恒定」）。trend 从 2.1 dB 压到 0.4 dB，代价是颤音  
   也被压平（实测颤音深度掉到 1.3 dB，听着会"僵"）。

结果是能听，但本质是在修一个不该用的素材。**源不对，修得再好也是将就。**

### 9.3 换源：VSCO 2 Community Edition 的独奏小提琴

FreePats 没有弦乐，Sonatina 官网已死（204），archive.org 走代理 502。  
能下、能商用、**真的带稳态**的是 VSCO 2 CE：

```
https://github.com/sgossner/VSCO-2-CE/tree/master/Strings/Solo Violin/Arco Vib
许可证 CC0（仓库根 LICENSE）
30 个文件 / 70.9 MB / 44.1k 16bit 立体声
命名 LLVln_ArcoVib_{音名}{八度}_{p|f}.wav
音域 A3–C7（MIDI 55–96），大三度间隔取样，p / f 两档力度
```

单个音约 16 秒，**0.5 秒进入稳态，之后 14 秒都在 ±2 dB 内起伏**——那是弓压和  
颤音的自然变化，不是渐强。这才是做持续音该有的素材。

下载走 `gh-proxy.com` 前缀（实测 91 MB/s），直连 `raw.githubusercontent.com`  
在本机 schannel 握手失败。

落地产物：`D:/LMMS13/data/soundfonts/ViolinVSCO.sf2`（6.8 MB / 28 zones / 14 音 × 2 力度）。

**代价要说清楚**：

- **比 Iowa 亮**。频谱重心 3053 Hz，Iowa 2411 Hz，GM 2021 Hz。VSCO 是近场录音，  
  弓噪和擦弦细节多。写悲伤独奏很贴，写"远、厚、糊"的铺底反而要先压 3–5 kHz。
- **三度间隔要拉伸**。14 个音覆盖 55–96，每个 zone 最多拉 ±1.5 个半音，共振峰  
  会有轻微偏移（Iowa 是逐音采样，没有这个问题）。
- **它是 `Arco Vib`——强颤音**。要"不颤的干净长音"它给不了，那种段落用  
  `Violin Section` 或用合成器 pad 垫。

### 9.4 选循环点时加一个 trend 惩罚

`iowa_violin.find_loop()` 现在多一个 `trend` 参数（默认 0，即只用相位相关）：

```python
def flatness(ls, le):        # 不是极差，是首尾落差
    seg = env[ls:le]; q = len(seg) // 4
    head, tail = np.mean(seg[:q]), np.mean(seg[-q:])
    db = abs(20 * np.log10(tail / head))
    return 1.0 / (1.0 + trend * db)
score = phase_corr * flatness(ls, le)
```

实测（VSCO 源，28 zones）：

| trend 参数 | 循环内 trend    | trend p90   | 颤音范围    |
| -------- | ------------ | ----------- | ------- |
| 0（纯相位）   | +1.25 dB     | 4.53 dB     | 4.71 dB |
| **0.35** | **−0.25 dB** | **0.70 dB** | 3.93 dB |
| 0.6      | −0.24 dB     | 0.76 dB     | 3.88 dB |

0.35 之后收益就停了，再加大只是白牺牲颤音。**用 0.35。**

### 9.5 ⚠️ 最严重的一个坑：`sampleID`（gen 53）必须是最后一个 generator

这条比音色重要得多。

**症状**：音色能正常出声，但**长音 0.7 秒左右就断了**，循环完全不生效。而且  
它不报错——`sf2_audit` 显示 looped samples 111/111，`sf2_loopcheck` 的接缝  
指标漂亮到 1.03，全都在骗人。

**根因**：`sfz2sf2.build_sf2()` 把 instrument zone 的 generator 按这个顺序写：

```
43 keyRange, 44 velRange, 58 rootKey, **53 sampleID**, 54 sampleModes, 34 attack, 36 decay, 38 release
```

SF2 规范要求 **`sampleID`(53) 是 instrument zone 的最后一个 generator**。  
严格的播放器遇到 53 后面还有东西，会把整个 zone 判为无效——采样照样被载入  
发声（因为 `sf2_audit` 读到的是合法数据），但 `sampleModes`(54) 被丢掉，于是  
**只播一次就停**。

对照 FluidR3 的真实排布：`43, 52, 3, 50, 2, 45, 54, 58, 17, **53**`——编号根本不  
升序，但 53 稳在最后。

**修法**：把 53 挪到列表末尾，其余保持相对顺序。

**修复前后（渲染 4 小节 A3，音符本身 12.6 秒）**：

| 库                  | 修前实际发声  | 修后          |
| ------------------ | ------- | ----------- |
| AccordionHN.sf2    | 2.17 s  | **12.68 s** |
| ViolinIowa.sf2     | 0.76 s  | **12.78 s** |
| ViolinVSCO.sf2     | 0.76 s  | **12.76 s** |
| FluidR3_GM.sf2（对照） | 12.86 s | 12.86 s     |

**这条让前两轮所有"循环质量"的指标全部作废**——采样里确实有 loop 点，写得  
也不算差，但 LMMS 从来没用过它们。手风琴那次"循环接缝 1.31 → 0.68"的对比  
因此毫无意义。

**教训**：量化之前先确认「这条路径到底有没有被播放器采用」。一个能渲染出声音  
的 SF2 不代表它的 generator 被接受。`_loop_probe.py` 就是干这个的——渲染一个  
4 小节长音，看最后一个超过 −40 dB 的点落在哪里。**新音色入库前必须跑一次。**

## 10. 一句话总结

> **LMMS 的音色天花板不在引擎，在格式。**  
> SF2 是唯一能稳定落地的采样路线；SFZ 和 VST3 再好也得先转换或外部渲染。  
> 而 GM 之所以廉价，是因为「100% 循环采样 + 强弱只改音量」——  
> 换成 24 秒自然衰减、真换采样的 Salamander，同一个 LMMS 立刻不一样。
